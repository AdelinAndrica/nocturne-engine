## 3. Canonical documentation model

Created:

`Docs/Development/Documentation Model.md`

The current-behavior precedence contract is:

1. current canonical Architecture / Systems / Development contracts;
2. current source code for exact implementation behavior;
3. completion/implementation reports as evidence of delivered phase scope;
4. historical Phase documents for chronology and earlier design context.

Roadmap text defines assigned scope. It is not evidence that a future feature is implemented.

This prevents an old phase plan or intermediate implementation note from silently becoming the current engine contract.

## 5. Metadata contract

Canonical authored documents use constrained flat frontmatter.

Representative system metadata:

```yaml
---
id: "noc.resources"
doc_type: "system"
canonical: true
status: "implemented"
subsystem: "Resources"
phase_introduced: 4
description: "..."
source_files: ["Engine/Resources/ResourceManager.h"]
source_docs: ["Docs/Phase 4 — Resource Manager.md"]
book_grounding: ["Jason Gregory — Game Engine Architecture (3rd ed.), §7.2"]
---
```

Supported Nocturne metadata fields are:

- `id`;
- `doc_type`;
- `canonical`;
- `status`;
- `subsystem`;
- `phase_introduced`;
- `description`;
- `source_files`;
- `source_docs`;
- `book_grounding`.

The Starlight content collection extends its schema with the corresponding Nocturne fields.

The synchronization step additionally rejects:

- duplicate canonical IDs;
- generated path collisions;
- missing canonical `id`, `doc_type` or `status`;
- canonical system pages without `subsystem`;
- unsupported source-frontmatter fields;
- unsupported multiline/nested source-frontmatter forms.

## 11. 404 behavior

An initial attempt to supply a Starlight content entry for `404` revealed a route conflict with Starlight's own injected 404 route.

The final implementation:

- sets `disable404Route: true` in Starlight;
- provides `Website/src/pages/404.astro`;
- uses the common Nocturne site layout;
- links back to Documentation and the website home.

The previous route-conflict warning is gone in the validated final implementation.
